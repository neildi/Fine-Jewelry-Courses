# Measuring Training: Pre/Post KPI Design

Module 1 of this course taught trainers to name a KPI before building any content. This module closes the loop: how to actually measure whether that KPI moved, using a before-and-after comparison built into the training design from the start, not added as an afterthought once someone in leadership asks whether the training worked.

## Why This Matters

Training leadership in fine-jewelry retail is explicitly held to this standard already. A Director of Sales Training role must "track the effectiveness of training programs and demonstrate ROI in terms of increased sales and client satisfaction," and a fine-jewelry L&D role one level down is "explicitly measured on Conversion rates, Average transaction value, Client retention" — not on completion rates or attendance. This project's own course architecture reinforces the same standard: the KPI link stated for this course is "new-hire ramp time, post-training KPI lift," which means every module a trainer builds should be judged by that same lift, not by how the training felt to deliver.

## The Minimum Pre/Post Design

A usable pre/post measurement doesn't require a data scientist — it requires three things decided before training happens: which KPI (pulled from the outcome named in Module 1), what the baseline number is right now, and when the post-training number will be checked. This project's own C12 course already defines the KPI vocabulary (conversion, average transaction value, UPT, retention) a trainer should draw from rather than inventing new metrics.

| Element | Example |
|---|---|
| KPI (from Module 1's outcome) | Conversion rate on diamond inquiries |
| Baseline (measured before training) | 22% over the last 30 days |
| Training delivered | Five-day huddle sequence on the 4Cs discovery script (Module 2/3 format) |
| Check-in point | 30 days after the sequence completes |
| Post number | To be measured — compare against 22% baseline |

Without a written baseline captured before training starts, there is no way to credibly claim the training caused any later change — a post-only number tells you where things ended up, not whether training moved them.

## Choosing a Realistic Check-In Window

A KPI check run the day after training ends almost always shows nothing, because behavior change takes repeated practice to show up in numbers, and short-term fluctuation in a small sample (one store, one week) can mask or exaggerate any real effect. A jewelry-industry compensation guide referenced elsewhere in this catalog describes reviewing a new associate's progress "three months into the job" as a standard checkpoint — a useful anchor for how much time genuinely new behavior needs before a KPI comparison is meaningful, even though a shorter 30-day check is often reasonable for a narrower, single-behavior module rather than a full onboarding ramp.

**Trainer (setting up a measurement plan):** "We're not checking this tomorrow. Baseline is this month's conversion number. We deliver the five-day sequence, give it two full weeks of practice on the floor, then pull the same conversion number and compare — not because two weeks proves everything, but because it's enough time to see if the behavior is actually showing up, without waiting so long we lose track of what caused what."

## What to Do When the Numbers Don't Move

A pre/post comparison that shows no lift is not a failure of the measurement — it's exactly the signal Module 1 warned about: an outcome that isn't producing its linked KPI movement needs to be rewritten, not defended. The diagnostic discipline already built in C14's comparative-KPI module applies here too: before concluding the training itself failed, check whether the behavior was actually delivered as designed (did managers run the huddle sequence, per Module 4's train-the-trainer check), whether the KPI choice was realistic for what the training targeted, and whether the check-in window was long enough to detect a real signal.

**Trainer (diagnosing a flat result):** "Conversion didn't move. Before I rewrite the training, let me check three things: did every store actually run the five-day sequence, or did some skip it? Is 30 days really enough time for a new discovery script to show up in a conversion number? And is conversion even the right metric, or should I have been watching average transaction value instead?"

## Objections, Mistakes and Edge Cases

**Measuring completion or satisfaction instead of a KPI.** A 95% completion rate or a high satisfaction score answers a different question than "did the targeted behavior change and did the KPI move" — track both if useful, but never let completion data substitute for the actual KPI comparison.

**Skipping the baseline because training already happened.** If a baseline wasn't captured before training started, don't retroactively estimate one — flag the module as unmeasured this cycle and capture a proper baseline before the next iteration.

**Attributing every KPI change to training alone.** A conversion lift during a training rollout might be partly seasonal, partly a new product launch, partly the training — note other changes happening in the same window so a leadership conversation about results stays honest about what else might explain the number.

**Checking too early or never checking at all.** A check-in scheduled but never actually run defeats the entire design — put the check-in date on a calendar with a named owner, the same discipline C14's monthly business review uses for people-results follow-through.

## On the Floor: Applying It This Week

1. For your next training rollout, write down the exact KPI, the current baseline number, and the specific date you'll check it again — before delivering any content.
2. Pull the KPI vocabulary from this project's own C12 course rather than inventing a new metric for the module.
3. Choose a check-in window long enough for the behavior to show up in practice — typically at least two to four weeks for a single-behavior module, longer for a full onboarding ramp.
4. When a result is flat, run the three-question diagnostic (was it delivered as designed, was the KPI realistic, was the window long enough) before rewriting the training itself.
5. Note any other major change happening in the same measurement window (a promotion, a new product line, a staffing change) so any reported KPI lift can be discussed honestly.
