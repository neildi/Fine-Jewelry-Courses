# Curriculum Roadmaps by Career Stage

A trainer who has built strong individual modules — outcome-first, floor-format, with a scenario bank and a measurement plan — still faces one more design problem: which modules go to which learner, and in what order. A brand-new associate and a district leader in the same store need entirely different content, and handing either of them the wrong sequence wastes their time and yours. A curriculum roadmap solves this by mapping content to career stage before anyone asks "what should I learn next."

## Why This Matters

This project's own course architecture already contains a complete, tested version of this roadmap. Section A4 of the Prompt Kit lays out "persona-to-course learning paths" — a required course sequence for each of the nine personas this catalog serves, from "P1 New Associate" (C1 → C2 → C4 → C3 → C5) through "P8 Multi-Store Leader" (C12 → C14 → C13 → C10) and "P9 Sales Trainer" (C15 → C13 → C2 → C12). A free industry resource makes the same case at a broader level: NHPA's "Path to Success learning paths" are described as a "recommended learning path by career stage" moving from "foundational retail skills" to "leadership development," explicitly built as a "curriculum roadmap skeleton" reusable for exactly this purpose. Both sources converge on the same principle — training should be sequenced by where the learner is, not delivered as one undifferentiated pile of content.

## The Four Career Stages Already Defined

This catalog's own research already maps fine-jewelry retail careers into a general stage progression — Stage 1 (Entry/Individual Contributor), Stage 2 (Senior/Specialist), Stage 3 (Management), and Stage 4 (Multi-unit/Executive) — and pairs specific free resources to each stage's skill gaps. A curriculum roadmap for training design should map directly onto these same four stages rather than inventing a new career-stage framework, since the underlying skill and resource mapping has already been done.

| Career stage | Illustrative persona | What they need most | Existing course entry point |
|---|---|---|---|
| Stage 1 — Entry | P1 New Associate | Product vocabulary, a repeatable sales conversation, security habits | C1 → C2 → C4 |
| Stage 2 — Senior/Specialist | P4 Bridal Specialist, P6 Gemologist–Seller | Deeper product/technical fluency, specialized client conversations | C6, C7, C8 (specialist track) |
| Stage 3 — Management | P7 First-Time Store Leader | Operating systems, KPI fluency, hiring and coaching | C11 → C12 → C13 |
| Stage 4 — Multi-unit/Executive | P8 Multi-Store Leader, P9 Sales Trainer | Comparative diagnosis, district leadership, training design itself | C14, C15 |

## Building a Roadmap From Existing Modules, Not New Content

The most efficient curriculum roadmap a trainer can build reuses modules that already exist in this catalog rather than commissioning new content for every stage. A new associate's onboarding roadmap, for instance, doesn't need an original security module — it needs a scheduling decision about when C4's security content fits into the associate's first thirty days, sequenced alongside C1 and C2's product and conversation modules.

**Trainer (building a new-hire roadmap):** "We're not writing new content for onboarding. We're sequencing what already exists: C1's product modules in week one, C2's conversation modules in week two, C4's security module by week three, with C3's clienteling habits layered in throughout. The roadmap is the schedule, not new material."

This mirrors the free-resource "Quick-Start Curriculum Suggestion" already documented in this project's research — a first-30-days path for a new associate and a longer path for a store manager or district leader, both built entirely from existing named resources rather than freshly written content.

## Keeping the Roadmap Current as People Advance

A roadmap is not a one-time assignment — a learner who completes their Stage 1 sequence and gets promoted needs the next stage's roadmap waiting for them, not a gap while someone remembers to hand them new material. This connects directly to the succession and development work in C14's Module 7 (Talent Pipeline and Succession): a district leader identifying an associate as ready for promotion should already know which curriculum roadmap that associate moves into next, because the stage-to-stage handoff was designed in advance.

## Objections, Mistakes and Edge Cases

**Building a new roadmap framework instead of using the one this catalog already has.** The persona-to-course learning paths in Part A4 and the four-stage career map are both already built and internally consistent — a trainer designing curriculum roadmaps should adapt these, not create a parallel system with different stage names or sequencing logic.

**Treating every learner in a persona as identical.** A roadmap is a default sequence, not a rigid rule — a P4 Bridal Specialist who already has strong product knowledge from a prior job may skip ahead in the sequence, while one new to the trade follows it in full order.

**Forgetting to update the roadmap when new modules are added.** Every time a new course or module is added to this catalog (as this course itself is being built module by module), the relevant persona roadmaps should be checked for whether the new content belongs in the sequence.

**Assuming a roadmap replaces individual judgment.** A store manager or trainer should still adjust pacing for an individual learner's actual pace and gaps — the roadmap sets the default order, not a mandatory fixed calendar regardless of how someone is actually progressing.

## On the Floor: Applying It This Week

1. Pull the persona-to-course learning path for the role you train most often (new associate, store manager, etc.) directly from this catalog's own Part A4 rather than building a new sequence.
2. Map which of that path's courses/modules your team has already completed, and identify the next unstarted item in the sequence for each learner.
3. Build a simple stage-transition checklist: when someone completes their current stage's roadmap, what's the very next roadmap they should start.
4. Check whether any newly built modules (like the ones in this course) belong in an existing persona's roadmap, and add them if so.
5. Identify one learner whose actual pace or background justifies deviating from the standard roadmap order, and document why.
