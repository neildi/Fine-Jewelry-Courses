**1. What are the five specific, repeated failure modes behind unused SOPs identified in this module?**
A) SOPs fail randomly with no identifiable pattern
B) Written by someone who's never done the task, excessive length, poor accessibility (buried documentation), staleness (never updated), and lack of per-step ownership/accountability
C) SOPs only fail when they are too short, never when they are too long
D) The only real failure mode is poor formatting

**Correct answer: B**
Explanation: These five specific failure modes are confirmed across multiple independent sources analyzing why written procedures go unused, using nearly identical language.

**2. Why does this module argue that a chronically-ignored SOP is often a "systems-design problem" rather than a training or discipline failure?**
A) Ignored SOPs always indicate deliberate employee non-compliance requiring discipline
B) The process is often unclear at the exact point of execution, required information is scattered across tools, or the SOP adds administrative work without helping the person do the job faster — retraining alone doesn't fix this underlying friction
C) Training is always irrelevant to whether a procedure gets followed
D) Systems-design problems and training problems are identical and require the same fix

**Correct answer: B**
Explanation: This reframe means the more effective fix is usually redesigning the procedure itself, not simply repeating the same instruction that already wasn't working.

**3. What is the seven-element structure this module recommends for a genuinely usable retail SOP?**
A) Title, Author, Date, Signature, Approval, Filing, Archive
B) Task, Owner, Timing, Steps, Standard, Exception, Proof
C) Introduction, Background, Theory, Discussion, Conclusion, References, Appendix
D) SOPs require no consistent structure and should be written freely

**Correct answer: B**
Explanation: This specific structure names the task, who owns it, when it happens, the actual steps, what correct completion looks like, how to handle exceptions, and how completion gets proven.

**5. What drafting technique does this module recommend instead of writing an SOP from a generic template or theoretical ideal?**
A) Copying a template from an unrelated industry with no adaptation
B) Observing and documenting what the store's actual best-performing associate already does when running a task correctly, then formalizing that into the written procedure
C) Writing the SOP without ever observing how the task is actually performed
D) Asking the least experienced team member to write the initial draft

**Correct answer: B**
Explanation: This directly solves the "written by someone who's never done the work" failure mode, since the result reflects real, tested practice.

**6. Why does this module recommend piloting a new SOP with someone relatively new to the task, not just an expert?**
A) Novices should never be involved in testing new procedures
B) Testing with someone less familiar with the task surfaces the steps that read fine on paper but are unclear or impractical in actual execution, which an expert might not notice
C) Only experts can accurately evaluate whether an SOP is well-written
D) Piloting has no real value and should be skipped to save time

**Correct answer: B**
Explanation: A relative novice is more likely to reveal gaps that someone with tacit, unconscious knowledge of the task might not think to mention.

**7. What does this module recommend regarding when an SOP should be updated?**
A) SOPs should only be updated on a fixed annual schedule regardless of any actual process change
B) An SOP should be updated specifically whenever something changes that actually affects how the task is done (a new regulation, a new POS feature, a vendor-relationship change), not on an arbitrary disconnected schedule
C) SOPs should never be updated once written
D) Updates should only happen if a formal complaint is filed about the procedure

**Correct answer: B**
Explanation: Change-triggered revision keeps the document accurate to the real current process, rather than allowing it to quietly go stale.

A) The team was retrained extensively on the general concept of cash reconciliation

**Correct answer: B**
Explanation: This illustrates the module's core point: the original SOP itself was the problem, not the team's discipline or knowledge.
