# C8-M01 Fact-Check: The Repair and Custom Design Continuum

## Verification Status: Job-tracking status sequences and communication cadence strongly cross-corroborated across jewelry-specific software sources; four-tier continuum framework is this module's own original organizing synthesis

## Claims Reviewed

**1. The four-tier complexity continuum (simple bench repairs, moderate repairs/restoration, redesign/remounting, fully custom design).**
Status: This specific four-tier framing is this module's OWN ORGANIZING SYNTHESIS, created to structure this course, rather than a direct quotation of an identical framework from a single external source. However, each tier's description is grounded in real job-type distinctions found across the sources reviewed (e.g., Nobbier's bench-jeweler article explicitly distinguishes routine repair work from custom design work with different skill emphases; PrismaNote's and MJJ Brilliant's guides describe repair-specific workflows that are consistent with this module's "simple" and "moderate" tiers).

**2. Consistent job-status tracking sequence (intake, awaiting approval, in progress, quality check, ready for pickup) and core intake data fields (customer details, item description, photos, estimated cost, target date).**
Status: CONFIRMED CONSISTENT across seven independent jewelry-specific repair/POS software sources: WJewel (explicitly describes "received → in-progress → complete → ready for pickup" plus intake fields matching this module's description), Jooli POS ("barcoded ticket, photo record, assigned jeweler, live status from drop-off to pickup"), RepairSuite (a detailed five-step visual workflow matching this module's sequence closely), PrismaNote (an eleven-stage version covering the same core touchpoints in more granular form), BusinessMind, Luxare, and PIRO Retail. This level of independent cross-source agreement, all describing highly similar sequences using different specific software products, gives strong confidence in this general industry pattern.

**3. Bench jewelers working fluidly across repair and custom-design work, combining traditional hand skills with CAD/3D printing.**
Status: Sourced from Nobbier's "What is a Bench Jeweler" article, which explicitly describes both routine repair/quality-assessment work and CAD/3D-printing-assisted custom design work as part of the bench-jeweler role. Corroborated qualitatively (not with specific statistics) by a Reddit r/jewelers community thread describing genuine variation in work mix across different types of jewelry-repair shops, supporting the general point that the same role can span a wide complexity range depending on the specific shop.

**4. Client-communication cadence (intake confirmation, approval, updates, completion notification, pickup reminder) as a five-step touchpoint sequence.**
Status: Sourced directly from MJJ Brilliant's wholesale-repair-program guide, which explicitly lists this exact five-step sequence ("Intake confirmation. Evaluation or estimate approval, where required. An update if scope, pricing, or timing changes. Completion notification. Pickup reminder or shipping confirmation."). Cross-consistent with PrismaNote's more granular eleven-stage repair-process guide, which covers the same underlying touchpoints (registration/assessment/quotation/approval/scheduling/workshop/quality-check/communication/payment/collection) in more detail.

**5. Chain-of-custody logging practice (recording every handoff against a single unique job ticket).**
Status: Sourced directly from MJJ Brilliant's guide, which explicitly describes this exact chain-of-custody workflow ("Retail counter to secure store storage. Store to outbound shipment or repair pickup. Repair partner back to the retailer. Retailer to customer pickup or final shipment") specifically in the context of repair outsourcing. This module treats the underlying principle as applicable across the whole continuum (not just outsourced work), which is a reasonable, though not separately re-verified, extension of the source's specific outsourcing-focused framing.

**6. Worked scenario and practice exercise.**
Status: ORIGINAL illustrative synthesis created for this module, not drawn from any external source.
