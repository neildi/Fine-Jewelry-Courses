# C12-M06 Huddle Card: Building the Weekly Dashboard

## 5-Minute Pre-Shift Discussion

**The one idea to remember:** A dashboard with 20 numbers on it gets ignored. A dashboard with 5-8 numbers, each with a comparison next to it, gets used every week.

## Four Rows, Four Questions
1. **"Was the period good?"** — sales vs. plan, transactions, margin, GMROI, sales/sq ft
2. **"Is it demand or basket?"** — traffic, conversion, ATV, UPT
3. **"Is it inventory?"** — sell-through, turn, out-of-stock on top sellers
4. **Drill-down** — only when Rows 1-3 flag something specific

## Outcome, Driver, or Diagnostic?
- **Outcome** = the few numbers leadership checks every week (sales vs. plan)
- **Driver** = explains WHY the outcome moved (conversion rate)
- **Diagnostic** = only pulled up when something's actually wrong (which associate, which SKU)

## Never Show a Number Alone
11% conversion means nothing by itself. 11% vs. last month's 15% means everything. Every number needs a comparison next to it — plan, last year, trailing weeks.

## Why Dashboards Die by Month Three
Manual retyping is exhausting and someone eventually skips a week, then skips it forever. Export data straight from the POS. Keep raw data separate from your formulas. Build each formula once.

## Build One Row at a Time
Don't try to build all three rows on day one. Get Row 1 running reliably first. Then add Row 2. Then Row 3.

## Today's Discussion Prompt
If we built just Row 1 this week, using only numbers we can pull straight from our POS, what would it show us right now?
