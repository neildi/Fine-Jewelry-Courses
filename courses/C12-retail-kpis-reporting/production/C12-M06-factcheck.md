# C12-M06 Fact-Check: Building the Weekly Dashboard

## Verification Status: All core structural claims in this module (5-8 KPI limit, four-row structure, outcome/driver/diagnostic framework, comparison-point principle, export-based build discipline) are CONFIRMED across multiple independent, credible retail-dashboard-design sources; no MUST VERIFY items identified

## Claims Reviewed

**1. The "5-8 headline KPIs" dashboard design principle.**
Status: CONFIRMED CONSISTENT across multiple independent dashboard-design sources: ThoughtSpot's "Dashboard Design: Examples and Best Practices" ("5-7 primary KPIs per dashboard view to avoid information overload"), Setproduct's "Dashboard UI design" ("Keep the first viewport to three or four KPIs at most, because anything more turns into a scroll people abandon"), and vidi-corp.com's "7 Store Performance Dashboards" ("Aim for five to eight headline KPIs per page, and leave out anything that doesn't change a decision"). These sources converge on a consistent general range (roughly 3-8, with most clustering at 5-8) even while using slightly different exact numbers, which this module rounds to "roughly five to eight" to reflect the range across sources.

**2. The four-row dashboard structure (Row 1: "was the period good?"; Row 2: "is it demand or basket?"; Row 3: "is it inventory?") with specific metrics assigned to each row.**
Status: CONFIRMED, sourced directly and specifically from koronapos.com's "Retail KPI Dashboard: 15 Metrics, Formulas & Benchmarks" article, which explicitly names this exact structure with these exact questions and specific metric assignments (Row 1: net sales vs. plan, transaction count, gross profit margin, GMROI, sales per square foot; Row 2: foot traffic, conversion rate, ATV, UPT; Row 3: sell-through by category, inventory turnover, out-of-stock rate on top sellers). This is a single, detailed, directly-sourced structure rather than one independently corroborated across multiple sources, though it is internally coherent and consistent with general retail-KPI-hierarchy principles found elsewhere.

**3. The outcome/driver/diagnostic three-tier metric-classification framework.**
Status: CONFIRMED, sourced directly from umbrex.com's "Retail KPI Architecture and Metric Definitions" article, part of a broader, detailed "Retail KPI Dashboard & Weekly Business Review Playbook" series that explicitly defines this exact three-level structure with the stated "KPI tree principle."

**4. This module's application of the outcome/driver/diagnostic framework specifically to this course's own Modules 1-5 KPI vocabulary.**
Status: ORIGINAL synthesis created for this module, applying the confirmed framework above to content already established and independently fact-checked in this course's earlier modules; not itself an externally sourced claim.

**5. The always-pair-with-a-comparison-point principle.**
Status: CONFIRMED CONSISTENT across multiple independent sources: ThoughtSpot ("Use KPI tiles with time comparisons... trend indicators that show if they're up or down compared to the last period"), umbrex.com ("Metrics are shown against plan, prior year, forecast, trend, or benchmark where relevant"), and DataCamp's "Effective Dashboard Design" ("Add context (targets, benchmarks, time frames) near each chart so users don't hunt for meaning").

**6. The export-based, separated-tabs, single-formula-per-KPI build discipline, and the specific warning about manual-retyping dashboards collapsing by month three.**
Status: CONFIRMED, sourced directly and specifically from koronapos.com's article, which states this exact practical build guidance ("Export, do not retype... Manual entry is what kills these files by month three... One tab per subject area... Build the formulas once... Chart on a summary tab. Nothing on the summary tab should require typing.").

**7. The weekly-meeting structure (30 minutes, same day each week, specific metrics reviewed, concrete outputs).**
Status: CONFIRMED, sourced directly from the same koronapos.com article, which specifies this exact meeting cadence, duration, attendee list (owner/GM with store manager), metrics reviewed, and expected outputs.

**8. The staged build sequence (Row 1 first, then Row 2, then Row 3).**
Status: ORIGINAL synthesis created for this module, built as a practical extension of the confirmed four-row structure; not itself an externally sourced claim, though it is a reasonable, low-risk practical recommendation consistent with general project-management principles of incremental build-out.

**9. Practice exercise.**
Status: ORIGINAL synthesis created for this module, not an externally sourced case.
