# C12-M06 Outline: Building the Weekly Dashboard

## Module Metadata
- Course: C12 - Retail KPIs & Reporting for Jewelry Store Leaders
- Module: 6 of 8
- Persona: P7 (First-Time Store Leader), P8 (Multi-Store Leader), per official course architecture
- Working title: Building the Weekly Dashboard
- Learning objective: Store leaders can apply the "5-8 headline KPIs" design principle, structure a dashboard using the four-row (outcome/driver/inventory/diagnostic) framework, apply the outcome/driver/diagnostic metric classification to this course's own KPI vocabulary, always pair a number with a comparison point, and build a dashboard using an export-based rather than manual-retyping structure that survives past its first few months.
- Terminal outcome tie-in: Directly fulfills the C12 terminal outcome "build a weekly dashboard" per this project's official course architecture, and directly supports the course's stated capstone assessment (build and populate a dashboard from sample data).

## Section Map

1. **Why This Module Matters** — Frames the dashboard as the single view that makes Modules 1-5's KPI vocabulary actually usable together.
2. **The Core Design Principle: Fewer Numbers, Not More** — The 5-8 headline KPI limit, confirmed across multiple independent dashboard-design sources.
3. **A Four-Row Structure That Answers the Right Question at Each Level** — Row 1 (was the period good?), Row 2 (demand or basket?), Row 3 (inventory?), plus a drill-down fourth layer.
4. **Outcomes, Drivers, and Diagnostics: A Framework for Deciding What Goes Where** — The three-tier metric classification, applied explicitly to this course's own KPI vocabulary from Modules 1-5.
5. **Show Comparison, Not Just the Number Itself** — The always-pair-with-a-comparison-point principle, tied back to C12-M02's trend-based benchmarking.
6. **Building It Without It Collapsing by Month Three** — Export-based structure, separated raw/calculated tabs, single-formula-per-KPI discipline.
7. **The Weekly Meeting This Dashboard Actually Supports** — The specific weekly-review meeting structure this dashboard enables, tied to C11-M10's weekly scorecard.
8. **Putting the Vocabulary to Work** — The practical, staged build sequence (row 1 first, then row 2, then row 3).
9. **Practice Exercise** — Sketching a four-row dashboard and identifying one buildable row for this week.
10. **Key Takeaways** — Five-point recap.

## Production Notes
- The "5-8 headline KPIs" design principle is CONFIRMED CONSISTENT across multiple independent dashboard-design sources: ThoughtSpot's "Dashboard Design: Examples and Best Practices" (explicitly stating "5-7 primary KPIs per dashboard view to avoid information overload"), Setproduct's "Dashboard UI design" (recommending "three or four KPIs at most" in the first viewport), and vidi-corp.com's "7 Store Performance Dashboards" (recommending "five to eight headline KPIs per page"). These sources converge on a consistent range even while using slightly different exact numbers, which this module rounds to "roughly five to eight" to reflect the range across sources.
- The four-row dashboard structure (Row 1: was the period good?; Row 2: demand or basket?; Row 3: inventory?) is sourced directly and specifically from koronapos.com's "Retail KPI Dashboard: 15 Metrics, Formulas & Benchmarks" article, which explicitly names this exact structure with these exact questions and the specific metrics assigned to each row. This is CONFIRMED as a directly, specifically sourced structure from a single detailed source.
- The outcome/driver/diagnostic three-tier metric-classification framework is sourced directly from umbrex.com's "Retail KPI Architecture and Metric Definitions" article (part of a broader "Retail KPI Dashboard & Weekly Business Review Playbook" series), which explicitly defines this exact three-level structure ("KPI tree principle: every dashboard metric should either measure an outcome, explain a driver, or trigger a management action"). This module's application of this framework specifically to this course's own Modules 1-5 KPI vocabulary is this module's own original synthesis, not itself an externally sourced claim, though it accurately reflects the confirmed formulas and definitions established in those earlier modules.
- The always-pair-with-a-comparison-point principle is CONFIRMED CONSISTENT across multiple sources: ThoughtSpot ("Use KPI tiles with time comparisons... trend indicators that show if they're up or down compared to the last period"), umbrex.com ("Metrics are shown against plan, prior year, forecast, trend, or benchmark where relevant"), and DataCamp's "Effective Dashboard Design" ("Add context (targets, benchmarks, time frames) near each chart so users don't hunt for meaning").
- The export-based, separated-tabs, single-formula-per-KPI build discipline (and the specific warning that manually retyped dashboards "kill these files by month three") is sourced directly and specifically from koronapos.com's article, which provides this exact practical build guidance.
- The weekly-meeting structure (30 minutes, same day each week, specific metrics reviewed, ending in concrete outputs: next week's schedule, promotional focus, one coaching target per associate) is sourced directly from the same koronapos.com article.
- The staged build sequence (row 1 first, then row 2, then row 3) is this module's own original synthesis, built as a practical extension of the confirmed four-row structure above; not itself an externally sourced claim.
- The practice exercise is an ORIGINAL synthesis designed for this module, not an externally sourced case.
